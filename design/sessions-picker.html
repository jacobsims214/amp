/sessions — pick up a chat from this directory

The directory-scoped session picker, inside the boxed chat layout approved in #2881. One panel, three stages (browse → confirm → resumed), and every failure it can hit: nothing here, still scanning, damaged files, another process holding a session, and the manager mid-reply.

Browse stage. Opened with /sessions while idle. The Sessions box takes the panel slot and the focus (brighter border, keys in the bottom border); Message steps back.

  • Cursor starts on the most recent session that isn't the current one. The current session stays in the list, marked, so “did it save?” has an answer.
  • The · current tag is the surface; selecting it resumes nothing (it's a no-op row, skipped by ↑↓ — Enter on it is impossible).
  • Title carries the scope (“this directory”) and the count; the footer shows the full scope path when it matters.

Confirm stage. Enter on a row asks once, in place of the list: what you're resuming, what happens to the chat you're in, and what does not happen.

  • “The current chat stays saved as b2c4…” — the resume never destroys the session you're leaving.
  • “continues in the original file” — no copy, no fork: JsonlSessionStorage::load on the same path, hot-swapped (KB §6.5).
  • “does not re-run its tool calls or re-dispatch its workers” — display-only restore plus ToolReplay::Never (KB §4).
  • Esc steps back to the list with the cursor where it was.

Resumed. The picker is gone, the restored transcript is in the Conversation box, and one line records what happened.

  • The ✓ resumed line carries the short id, age, message count and the file it continues in — the same facts chat.rs::exit_line gives on quit.
  • The restored history renders through the same read-only blocks as a watched worker session (KB §4): the model was not called, nothing re-ran.
  • The next prompt continues the conversation from its own context; run numbering keeps the chat's numbering (process-scoped, KB §6.3).

Busy refusal. /sessions while the manager is replying (or prompts are queued) does not open the picker.

  • One flag-coloured notice in the transcript says why and when to retry; the spinner keeps running.
  • Same guard shape as /server's switching lock and quit's Shell::settled() predicate (KB §3): switching sessions is refused, not queued, so no selection state can collide with an in-flight turn.

Empty. First chat in this directory, or every stored session belongs to another cwd.

  • Says the scope plainly (“this directory”, and the path in dim), and that starting a chat creates one.
  • No cross-directory restore (plan assumption): the picker never offers sessions from other directories, so the empty state is where that boundary is stated.
  • Esc closes; the box is as short as the message needs.

Loading. The scan of ~/.local/state/amp-harness/sessions/*/*.jsonl filtered by header cwd is fast, but a first-open on a cold disk can take a beat.

  • Same spinner glyph and placement as the Message box's “manager replying” — the panel keeps its height so nothing jumps when rows arrive.
  • Esc cancels the scan and closes; a scan that fails lands on the problems layout with one row for the error.

Problem rows. Files the scanner found for this directory but can't offer, kept visible with the reason — the alternative is silently missing sessions.

  • unreadable — permissions or I/O error reading the file. Reason names the OS error; the row is dimmed and skipped by ↑↓.
  • older format — header parsed but the version predates the loader (JsonlSessionStorage::load can't replay it). The only two-line problem row: its file name rides under the id, because that's the row where someone goes to the file by hand.
  • locked · running elsewhere — another live harness holds it (the remote-live/ lock record, KB §3). Resuming it would fork the file, so it's refused in the list, not after a failed swap.
  • Good rows still work normally; problems never block the rest of the list.

What to decide

  1. Two-line rows with a preview (proposed — picking is the job, and the last message is what jogs memory) or one-line rows (id · age only), which fits 9+ sessions but makes “which one was that?” guesswork.
  2. Confirm stage on Enter (proposed, follows /questions) or Enter resumes immediately and Esc-undo via a notice. The confirm is one extra keystroke against resuming the wrong chat with no undo.

Guards (when /sessions does nothing)

  • Manager replying or prompts queued → one transcript notice (Shell::settled(), the quit predicate; same as the /server switching guard, KB §3).
  • Another device driving via remote → same refusal: the remote link's feed would cross two sessions (KB §6.3.3).
  • Live workers → not a refusal: workers survive the switch (project-scoped, not session-bound, KB §6.3.8). The confirm copy doesn't mention them.

Where each fact comes from

Row content → code

  • short id — first/last 4 of the session id, as chat.rs::session_id already displays.
  • age — file mtime (JsonlSessionMetadata.modified_at), relative (“2h ago”); the sort key too.
  • role — the directory name under sessions/ (manager/, a ticket number); shown only when it isn't manager, the default.
  • preview — last user or assistant text from a tail read, one line, ellipsized at the box width; skipped for problem rows.
  • scope — header cwd exact canonical match (KB §1); worktree sessions stay in their worktree's list.

States → mechanisms

  • resume — AgentHarness::set_session over JsonlSessionStorage::load (KB §6.5); rejects LaneBusy itself, the busy refusal is belt-and-braces UI.
  • unreadable / torn — the scanner's skip policy surfaces as a row instead of a skip (list_typed skips unparseable headers, KB §1).
  • locked — <state>/remote-live/ record exists for that session file (KB §3.3).
  • older format — header v below what JsonlSessionStorage::load accepts.
