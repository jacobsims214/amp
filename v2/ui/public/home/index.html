The flight loop

Plan the trajectory. Approve the burn. Land the work.

Every mission in AMP flies the same loop. Agents do the heavy lifting; a person gives the go at the moments that matter.

01

Plan

Your agent turns a goal into epics, stories and small tickets, wired as a dependency graph. Everything with its dependencies done can fly at once.

amp_create_tasks · amp_check_plan
02

Go / No-Go

The plan check polls the graph: anything isolated, too wide, or missing context gets a NO-GO. Then you approve your own agent's plan.

Flight plan · amp_approve_plan
03

Fly

Your agent dispatches only your tickets to worker agents. Questions come back to a human; quiet tickets get flagged and recovered.

amp_dispatch_task · questions · quiet
04

Review

Review gates between waves turn problems into fix tickets wired into the next gate, so nothing ships on a broken stage.

review gates · fix tickets
05

Land

Branches, commits and PRs are recorded on every run. Merges clear the queue, and day reports close the shift.

amp_list_unmerged · day reports
Humans + agents, in harmony

One crew. Clear chain of command.

People own the work; agents fly it for their person. Nobody's agent touches someone else's ticket, and every decision has a human name on it.

Your agent, your tickets

Each ticket has one human owner. Your manager agent runs only yours, and AMP refuses to dispatch anyone else's, so two engineers' agents never collide on the same project.

Artifacts

See it before it's built

When work needs a person's eyes first, an agent publishes it to AMP: an interactive mockup, a diagram, an image or a document. It asks for your review on its ticket and stops. Approve or request changes in AMP, or just tell your agent. The verdict lands on the ticket, and the build tickets fly against the version you approved.

HTML mockupsSVG diagramsimagesPDFs & docs
A person decides

Only people approve. An agent can publish and revise, but never sign off on its own work.

Versions

Every revision is a new version of the same artifact, previewed at phone, tablet and desktop widths beside its ticket's thread.

Design systems

Your org's design system, and each product's additions, are built the same way: phase by phase, each approved before it's published to the knowledge base for every agent to follow.

Safe to open

Artifacts run in a sandbox that can't reach your AMP session. Every view is audited, and unkept artifacts expire after 45 days.

Install the plugin

Dock your harness in two minutes

AMP ships a plugin for Claude Code and one for opencode. Each brings the whole crew: the manager agent and its worker, designer, reviewer and research specialists, AMP's skills, and the AMP, library-docs and browser MCP servers, connected to your AMP.

Claude Code plugin marketplace

Install · Claude Code
# 1. Point the plugin at your AMP (add this to your shell profile)
export AMP_MCP_URL=https://<your-amp>/mcp

# 2. Add AMP's marketplace and install the plugin
claude plugin marketplace add jacobsims214/amp
claude plugin install amp@amp
  1. Start Claude Code, open /mcp and sign in to amp with your AMP account.
  2. Run /amp:manager onboard me. Your session becomes the manager and walks you through AMP in your own projects.

Already in Claude Code? /plugin marketplace add jacobsims214/amp, then /plugin install amp@amp, does the same.

opencode opencode 2 plugin

Install · opencode
# 1. Get the plugin
git clone https://github.com/jacobsims214/amp
cd amp/v2

# 2. Add it to your global opencode config
./scripts/setup-opencode.sh --url https://<your-amp>/mcp
  1. Sign in once with opencode mcp auth amp, or add --token with an API token from Agents & tokens.
  2. Start opencode. The manager is your default agent: ask it to onboard you.

Each agent runs on the OpenRouter model AMP picked for its role. Add --inherit-models to run them all on your own default model.

Another MCP client? Connect it to https://<your-amp>/mcp with OAuth, or with an API token from Agents & tokens. AMP's built-in guide teaches any agent the rest.

Open source

Built in the open. Fly it anywhere.

AMP is open source under the Apache License 2.0. Its code, Helm chart, agent harness templates and built-in guide all live in one public repository. Read how it works, run it on your own cluster, and send improvements back.

github.com/jacobsims214/amp The AMP guide Harness templates Apache-2.0
API

Go, with one actor per project, epic, story and ticket, so the dependency graph unblocks itself. Runs as any number of replicas.

MCP

Streamable HTTP with OAuth or API tokens. Claude Code and opencode each get a plugin; everything else speaks MCP.

Knowledge

Typesense hybrid search over markdown knowledge bases, with local embeddings.

Identity

Dex for sign-in (local users or your SSO), oauth2-proxy for the browser, Envoy at the edge.

Launch your own station

To fly AMP today, deploy the chart

There's no hosted AMP yet. Every AMP is self-hosted from one Helm chart that brings the whole stack: Postgres, sign-in, the API, the UI, search and the indexing queue. Images are published to GitHub's registry.

You need

A Kubernetes cluster with cert-manager and the CloudNativePG operator, a DNS name for AMP, and Helm.

Then

Sign in as the bootstrap admin, create an org and a team, then install the plugin for your harness.

Deploy architecture · Connecting Claude Code and opencode

Deploy · helm 
# 1. Get the chart
git clone https://github.com/jacobsims214/amp
cd amp/v2/deploy/helm/amp
helm dependency build

# 2. Start from the production values and set your own:
#    global.domain, global.bootstrapAdminEmails,
#    storage classes, and global.imageTag
cp values-production.yaml my-values.yaml

# 3. Launch
helm install amp . -n amp --create-namespace -f my-values.yaml

# 4. Sign in, then install the plugin for your harness (see Install)
